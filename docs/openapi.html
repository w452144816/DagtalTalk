数字人 AI 服务端接口（多机方案） (0.1.0-draft)

Download OpenAPI specification:Download

依据《AI服务多机方案》（2026-10-18 方案稿，尚未落地）整理的接口文档。

三组接口：

  • /v1/*：给业务后端调（服务到服务），Authorization: Bearer <服务密钥>。
  • /rt/*：给前端浏览器调（实时通话），凭后端转交的会话 ticket（X-Session-Ticket 头，SSE/WS 用 ?ticket=）。ticket 绑定单个会话，短时有效，HMAC 签名无状态令牌，主备切换后仍有效。
  • /internal/*：控制面 ↔ 节点内网接口，只绑内网网卡，X-Node-Token 鉴权。

通用约定：

  • JSON；错误统一 {"error":{"code","message","retry_after?"}}。
  • 创建类请求支持 Idempotency-Key 头：主备切换时后端重试不会重复建会话/形象。建会话另由节点兜底：biz_ref 相同且在线的会话直接返回已有 session_id。
  • ID 前缀：av_ 形象、var_ 形象变体、vc_ 音色、sess_ 会话、job_ 任务、ps_ 人设、mat_ 素材。
  • AI 侧不存用户信息，后端可传 biz_ref 透传，用于对账和回调关联。
  • 耗时操作（建形象 1~3 分钟、变体生成、人设构建）走「202 + job + 回调」。
  • 备控制面不持有 VIP 时拒绝 /v1、/rt，返回 503 + Retry-After。
  • X-Request-Id 从后端一路透传到节点。
  • 回调（AI → 后端 callback_url）见 webhooks：带 X-Signature: HMAC-SHA256(body, 回调密钥) 与 event_id（后端按它去重），失败按 1s/5s/30s/2min 重试。

生成形象变体（底板视频）

同一张脸换背景/服装/姿态/待机动作，H3 本地闲时生成。

  • priority=idle 只在闲时跑；normal 低峰即跑；urgent 走 MiniMax 云端 H3 API（按条计费，由后端决定）。
  • 产物流程：生成 → 首尾帧接缝检查（不达标换种子重试最多 3 次）→ 登记为 variant → 推送到所有节点 → 各节点 prewarm → 回调 variant.ready。

创建会话

调度到一张空闲卡并建会话，返回 session_id + 一次性 ticket，由后端转交前端。

  • 满员：503 capacity_full + retry_after；queue=true 时返回 202 {state:"queued", position}，排到后通过 SSE session.state_changed / 回调通知。
  • history：断线重连 / 切换节点后接着聊，由后端把最近几轮带回来。
  • 后端可在用户进入「准备页」时预建会话，idle_timeout_s 兜底回收。
  • persona 用 persona_id 且该人设 knowledge_mode=external 时，必须配 llm.mode=external，否则 400。
